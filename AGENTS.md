# Start here

This repository contains instructions, not an app to run. Read this file and route the request before building anything.

| User request | Skill to read |
| --- | --- |
| Tailored SaaS slides, or the first/deck part of a SaaS sales package | [stream-saas-deck](skills/stream-saas-deck/SKILL.md) |
| A SaaS demo website with recurring-subscription and usage-based stories | [stream-saas-demo](skills/stream-saas-demo/SKILL.md) |
| A full SaaS client package, or a request to “figure it out” from this repo | Read both SaaS skills. Research and choose the story once, build the demo, then align the deck with the working journey. |
| A general client demo outside SaaS | [stream-client-demo](skills/stream-client-demo/SKILL.md) |
| Adapt an existing deck for a school or another non-SaaS client | [stream-client-deck](skills/stream-client-deck/SKILL.md) |

Do not route SaaS requests to a school template. A source deck, client website and authorized sandbox are inputs supplied separately. Inspect the existing work before making a copy. Keep the source deck and other clients’ projects intact.

For a full package, keep one private manifest linking the website, recurring story, UBB story, presenter notes, copied deck, sandbox records and verification status. The website and slides must tell the same story, with the same product names, units, prices and branding.

Public client facts, proposed commercial terms and working sandbox capabilities are different things. Record the distinction in the presenter material. Keep credentials, private conversations, customer records and authenticated links out of the public repository.
